# Homelab Cert Manager – Roadmap & Milestones

## Project Context & Architecture Guidelines
- **Stack:** Go (Standard Library `net/http`, `crypto/x509`, `html/template`), Materialize CSS (local in `static/`), JSON-based storage in `data/`.
- **Core Philosophy:** Keep it simple for the user. No background automation bloat. Zero external runtime dependencies by default.
- **File Structure:**
  - `main.go`: Routing, HTTP/HTTPS server, auth middleware, template rendering.
  - `certificate.go`: Certificate generation, signing, listing, and file handling.
  - `rootcert.go`: Root CA management.
  - `settings.go`: App configuration (`data/settings.json`).

## Milestone 1: CSR Support (Certificate Signing Requests)
**Goal:** Allow users to upload or paste an external CSR (`.csr` / PEM) generated by third-party devices (NAS, switches, Proxmox, etc.) and sign it with the Homelab Root CA using only the Go standard library (`crypto/x509`).

### 1.1 Backend – CSR Parsing & Signing (`certificate.go`)
- [x] **Extend Certificate Metadata**: Detect whether a certificate in `data/` has a corresponding private key file (`.key`) or was created via CSR (`HasPrivateKey bool`).
- [x] **Implement `SignCSR(csrPEM []byte, validDays int) error`**:
  - Decode PEM block (`pem.Decode`) and parse via `x509.ParseCertificateRequest`.
  - Validate CSR signature using `csr.CheckSignature()`.
  - Extract Subject (`CommonName`, `Organization`, etc.) and SANs (`DNSNames`, `IPAddresses`, `EmailAddresses`, `URIs`) directly from the CSR.
  - Sign the certificate using the existing Homelab Root CA certificate and key (`x509.CreateCertificate`).
  - Save the signed `.crt` file in the `data/` directory so it appears in the main certificate table.

### 1.2 Backend – HTTP Handler (`main.go`)
- [x] **Add Route `POST /sign-csr`**:
  - Accept either a multipart file upload (`.csr` / `.pem`) or raw PEM text from a textarea field, plus the desired validity period in days.
  - Call `SignCSR` and redirect back to the dashboard with clear error/success feedback.

### 1.3 Frontend – UI Integration (`templates/`)
- [x] **Add "Sign CSR" Action**: Add a button next to the existing certificate creation trigger that opens a Materialize modal (`#sign-csr-modal`).
- [x] **Build CSR Modal**: Include a file input for `.csr` files, a fallback textarea for pasting `-----BEGIN CERTIFICATE REQUEST-----` blocks, and a validity days input pre-filled from `settings.json`.
- [x] **Update Certificate Table**: Show a `CSR` badge for certificates without a local private key and disable/hide the "Download Key" button for those entries.

## Milestone 2: Optional Pocket ID / OIDC Authentication
**Goal:** Support Passkey/SSO login via Pocket ID (or any standard OIDC provider) as a strictly optional opt-in feature, while preventing lockouts if the OIDC provider's own certificate expires.

### 2.1 Configuration (`settings.go` & `templates/settings.html`)
- [x] **Extend `Settings` Struct**:
  - `OidcEnabled bool`
  - `OidcIssuerURL string`
  - `OidcClientID string`
  - `OidcClientSecret string`
  - `OidcRedirectURL string`
- [x] **Environment Variable Overrides**: Allow optional configuration via Docker environment variables (`OIDC_ENABLED`, `OIDC_ISSUER_URL`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `OIDC_REDIRECT_URL`).
- [x] **Settings UI**: Add an OIDC configuration section to `templates/settings.html` (with a toggle switch and input fields).

### 2.2 Custom Root CA Trust Pool (`oidc.go`)
- [x] **Create Custom HTTP Client for OIDC**:
  - Load `x509.SystemCertPool()`.
  - Automatically read and append the local Homelab Root CA (`data/rootCA.crt`, `data/root-cert/*.pem`) to the `RootCAs` pool if it exists.
  - Inject this `http.Client` into the OIDC context (`oidc.ClientContext`) so the container trusts a Pocket ID instance secured by a Homelab Cert Manager certificate out of the box.

### 2.3 OIDC Authentication Flow (`oidc.go` & `main.go`)
- [x] **Add Dependencies**: Add `github.com/coreos/go-oidc/v3/oidc` and `golang.org/x/oauth2`.
- [x] **Implement `GET /auth/oidc/login`**:
  - Verify `OidcEnabled` is true.
  - Generate a cryptographically random `state` cookie (CSRF protection) and redirect the user to the Pocket ID authorization endpoint.
- [x] **Implement `GET /auth/oidc/callback`**:
  - Validate the `state` cookie.
  - Exchange authorization code for tokens using the custom HTTP client.
  - Verify the ID token using the OIDC verifier.
  - Issue the standard authenticated session cookie used by the existing auth middleware and redirect to `/`.

### 2.4 Login UI & Emergency Fallback (`templates/login.html`)
- [x] **Conditional OIDC Button**: When `OidcEnabled` is true, render a prominent "Sign in with Pocket ID / OIDC" button at the top of the login card.
- [x] **Keep Local Admin Fallback**: Keep the standard username/password form accessible (e.g., in a collapsible section "Local Admin Login (Fallback)") to prevent chicken-and-egg lockouts when renewing an expired Pocket ID certificate.
